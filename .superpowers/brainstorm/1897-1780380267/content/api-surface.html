Auth flow (NextAuth handles all of this)
Automatically mounted by the [...nextauth] route:
GET  /api/auth/session
POST /api/auth/signin
POST /api/auth/signout
GET  /api/auth/callback/google
GET  /api/auth/callback/github
middleware.ts intercepts every /api/resumes/* request — redirects unauthenticated calls before the handler runs.
Consistent error contract
Every error response follows this shape:
{
error: "Human-readable message",
code: "VALIDATION_ERROR"
}
Error codes:
UNAUTHORIZED — no valid session
NOT_FOUND — resume doesn't exist or belongs to another user
VALIDATION_ERROR — Zod parse failed (includes details array)
INTERNAL_ERROR — unexpected server error
Route handler pattern (every endpoint follows this)
1. getServerSession(authOptions) → 401 if no session
2. Parse + ZodSchema.safeParse(body) → 400 with details if invalid
3. await dbConnect() → pooled MongoDB connection
4. Mongoose query (always scoped to { userId: session.user.id })
5. Return NextResponse.json(result) or structured error
